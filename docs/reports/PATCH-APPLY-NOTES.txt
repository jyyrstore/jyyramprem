Final token contract
--------------------
1 TOKEN = 1 USER.

Owner generation:
- token starts unassigned (`assigned_user_id = NULL`);
- token is AVAILABLE for a 24-hour redemption window;
- any member may attempt redemption;
- the first successful redemption wins and locks the token to that user.

After redemption:
- `15_days` => access expires 15 days after redemption;
- `30_days` => access expires 30 days after redemption;
- `permanent` => access has no expiry.

The 24-hour value is never used as the member access lifetime. A redeemed token never becomes available again.

Historical data handling
-------------------------
The V7 migration keeps token/grant history. A historical token with exactly one distinct redeemer may be associated with that user. A token demonstrably shared by multiple historical users is revoked rather than inventing a new owner.

Legacy `expires_at` columns are retained as compatibility mirrors during migration; canonical runtime authorization uses `redemption_expires_at` and `access_expires_at`.
