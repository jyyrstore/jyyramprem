# JYY'R Amprem — Target Flow V3 (User Email)

## Primary flow

```text
USER INPUT
  ↓
Required email (must be accessible by the user)
  ↓
POST /api/generate
  ↓
Provider POST /api/v1/send-magiclink { email }
  ↓
Fresh magic link is delivered to the user's email
  ↓
User copies the fresh magic link
  ↓
POST /api/accounts/:id/verify-email { rawLink }
  ↓
Provider POST /api/v1/verify-account { email, rawLink }
  ↓
Portal validates provider verification + ID token claims
  ↓
Encrypted short-lived provider ID token is stored server-side
  ↓
USER CONFIRM
  ↓
POST /api/accounts/:id/apply-premium
  ↓
Provider POST /api/v1/apply-premium { email, idToken }
  ↓
Portal validates success + premium.status=success + premium.valid=true
  ↓
Stored provider ID token is deleted
  ↓
AMPREM BERHASIL
```

## Email rules

- Email field is required; empty input is rejected.
- The portal accepts normal user-owned addresses such as Gmail and other valid domains.
- No mailbox is generated by the portal in the primary flow.
- The portal validates syntax, but it cannot prove inbox access before the provider sends the message. The provider's delivery/send result remains the external signal.

## Security boundary

- No portal mailbox provider is part of the primary flow.
- No external mailbox credentials are generated, stored, or sent to Alightfree.
- Raw magic links are validated for HTTPS + approved Alight action-link hosts before provider verification.
- Provider ID tokens are never returned to the browser and are never logged.
- The provider ID token is encrypted at rest with `PROVIDER_TOKEN_ENCRYPTION_KEY` and is cleared after successful Premium activation or expiry.
- Premium activation is a separate authenticated action so verification alone cannot silently activate Premium.

## Quota / idempotency

- `/api/generate` retains the existing server-side idempotency key.
- Provider safety quota remains independent from user magic-link quota.
- User magic-link quota is consumed only after a confirmed successful Premium activation.
- Verification and Premium activation remain separate provider request-budget operations.
